# agent-harness

## ADDED Requirements

### Requirement: Every repository carries a complete, self-contained harness

An agent opened on a single repository SHALL have everything it needs to work: no
sibling repository, no global store, no machine-specific configuration, and **no
harness content fetched at run time** — skills, hooks, templates, agents and
commands are all committed.

The network remains necessary for what the network legitimately owns: restoring
packages, downloading the SDK during `setup-env`, and querying advisory databases.
Self-containment is about the harness, not about isolation from nuget.org.

Seventeen skills SHALL be committed in each repository, physically duplicated in
`.agents/skills/` and `.claude/skills/`.

The set SHALL be exactly: `ask-matt`, `improve-codebase-architecture`,
`setup-matt-pocock-skills`, `setup-pre-commit`, `to-questionnaire`, `to-spec`,
`to-tickets`, `triage`, `wait-what`, `writing-for-agents`, `tdd`, `code-review`,
`verification-before-completion`, `using-git-worktrees`, `diagnosing-bugs`,
`resolving-merge-conflicts`, `finishing-a-development-branch`.

Content SHALL come from the public upstream and SHALL be committed, never fetched
at run time. A repository-local command SHALL refresh them from upstream **and
commit the result**, so an update is a reviewable pull request rather than a silent
mutation. Symbolic links SHALL NOT be used: without
Developer Mode, a Windows checkout degrades them into text files containing the
target path.

#### Scenario: a repository cloned alone is fully operational
- **GIVEN** a fresh clone of any repository, with no other repository present
- **WHEN** an agent runs `./scripts/setup-env.sh --check`
- **THEN** it reports readiness or names precisely what is missing

### Requirement: Every repository declares its agent entry points

A repository SHALL carry, at its root, an entry point for **each** agent family, so
that no agent depends on another's configuration:

| File | Purpose |
|---|---|
| `CLAUDE.md` | Claude Code entry point — objective, layer, invariants, commands |
| `AGENTS.md` | Codex and cross-agent entry point, carrying the same content |
| `.claude/settings.json` | permissions, hooks, status line, environment |
| `.claude/agents/`, `.claude/commands/` | the repository's domain reviewers and commands |
| `.agents/skills/`, `.claude/skills/` | the seventeen vendored skills |

`CLAUDE.md` and `AGENTS.md` SHALL stay in agreement; a check SHALL fail the build if
their shared sections diverge. The previous ecosystem had no `AGENTS.md` anywhere,
leaving Codex with no entry point at all.

#### Scenario: an agent opened on a bare clone knows where it is
- **GIVEN** a fresh clone opened by any agent family
- **WHEN** the agent reads its own entry point
- **THEN** it finds the repository's layer, its invariants, its script verbs, and
  the constraint that its wrapper may reference only its binding

### Requirement: Agent hooks enforce what prose cannot

`.claude/settings.json` SHALL configure, at minimum:

- **`PreToolUse`** — refusing edits when `master` or `develop` is checked out, and
  running the credential detector before any write. The pattern SHALL name the
  branches this flow actually produces: there is no `release/*` branch, Release
  Please working on its own `release-please--*` branches, and a deny rule naming a
  branch the flow never creates is precisely the dead rule this requirement forbids.
- **`PostToolUse`** — running the formatter on written files.
- **`Stop`** — printing the pre-pull-request gate: tests run, coverage met,
  specification validated.

Hooks SHALL be committed, identical across repositories, and delivered by the
template. Deny rules SHALL name branches that actually exist in the repository; a
dead rule SHALL be reported by the ecosystem audit.

#### Scenario: an agent cannot edit a protected branch
- **GIVEN** an agent working with `develop` checked out
- **WHEN** it attempts to write a source file
- **THEN** the `PreToolUse` hook refuses the write and states that a feature branch
  and a worktree are required

### Requirement: The harness comes from a generated template, never synchronised

`Rinzler78.Templates` SHALL publish `dotnet new` templates that expand a complete
harness into a new repository. A generated repository SHALL NOT reference its
source. `Meta` SHALL hold no templates and SHALL NOT push into sibling repositories.

Drift SHALL be reported by a non-blocking job that compares the recorded template
version against the published one. Updating remains a deliberate pull request in
the repository concerned.

#### Scenario: the template bootstraps itself
- **GIVEN** the `Rinzler78.Toolkit` repository
- **WHEN** its own harness is regenerated by its own template
- **THEN** the result is byte-identical to the committed harness
